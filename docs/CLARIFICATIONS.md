# Принятые уточнения и допущения

Основание: ответы экспертов, переданные модератором 19.09.2026, и материалы встречи 16.09.2026. Исходная переписка не публикуется. Уточнения отделены от технических решений прототипа.

| Тема | Уточнение | Реализация / ограничение |
|---|---|---|
| Приоритет | Авария → подключение → ремонт/дозаказ | Приоритет при рассмотрении заявок эвристикой; численные веса не заявляются |
| Длительность | Нормативы 90/100/40/50 мин включают 20 мин дороги | Принято допущение: работа+документы 70/80/20/30, дорога рассчитывается отдельно. Замена нормативной дороги требует подтверждения постановщика |
| Время | Окно ограничивает начало; раньше можно ждать | Конец работы может выйти за окно, но не за смену |
| Авария | Учитывать время фактического поступления | Новая заявка с типом «Авария» и полем времени поступления; выезд на неё не начинается раньше поступления |
| Статусы | Факт выполнения фиксирует диспетчер | Поддержка сообщает готовность, диспетчер закрывает; фактические назначения сохраняются |
| Оборудование | Выдаётся на весь день; при перепланировании проверять наличие | Демонстрационный расходуемый ресурс — роутеры; дневной запас на специалиста поддержки |
| Компетенции и транспорт | Отсутствующие данные можно моделировать | Редактируемые допуски специалистов поддержки; транспорт и смена из Dataset |
| Участки | Независимые сценарии | Одна сессия = один участок и один день |
| Динамика | Для хакатона достаточно статического плана, динамика дополнительная | Реализованы ручные назначения, создание, отмена, изменение условий и фактические статусы |
| Данные | Для расчётов нужны предоставленные синтетические CSV | Пока используется UI-демонабор; импорт исходных CSV и геокодирование остаются задачами |
| Маршруты | Допустимо усреднять движение общественного транспорта | Геодезические расстояния и средние скорости; дорожная сеть не подключена |

Встреча и исходное ТЗ расходятся в обязательности baseline и динамического события. Оба сценария сохраняются как полезные возможности. Изменение клиентского окна допускается в форме, но считается согласованной корректировкой исходных условий; солвер никогда не меняет окно самостоятельно.

Будущие задачи: дорожная матрица, геокодирование и исходные CSV; серверное хранение и авторизация; более полный склад; фактическое положение и задержки; размещение в Яндекс Облаке.
