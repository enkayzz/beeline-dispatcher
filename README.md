# Контур — помощник диспетчера

Интерактивный UX/UI-прототип для кейса «Билайн Бизнес»: рабочий день выездных инженеров, карта, расписание, объяснения назначений и перепланирование после срочной заявки.

## Запуск

Используйте Node.js 24 и npm; версия зафиксирована в `.nvmrc` и CI.

```bash
git clone https://github.com/enkayzz/beeline-dispatcher.git
cd beeline-dispatcher/frontend
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно http://127.0.0.1:5173).

```bash
npm run build
npm run preview -- --port 4173
```

Сборка находится в `dist/`. Её нужно раздавать через HTTP; открытие `index.html` через `file://` не поддерживается. Для переноса на другой компьютер скопируйте проект без `node_modules`, затем выполните `npm ci`.

## Что можно попробовать

1. Нажать **«Построить план»**. По умолчанию открыт синтетический день: 12 заявок, 5 инженеров, Москва, 17 августа 2026.
2. Выбрать инженера, посмотреть его точки и переключиться на **«Расписание»**.
3. Открыть заявку на карте, в расписании или таблице. Карточка показывает исполнителя, прибытие, начало, завершение и проверенные ограничения.
4. Открыть **«Внимание диспетчера»**: у аварийной заявки в велозоне нет инженера с одновременным совпадением навыка и транспорта.
5. Нажать **«Событие дня»**, добавить срочную заявку в 11:00. Начатые раньше работы сохраняются, оставшиеся заявки перепланируются.
6. Открыть **«Эффективность»**: базовый/предложенный планы, пробег каждого инженера и назначения до/после события.
7. Загрузить JSON, скачать пример или экспортировать рассчитанный план кнопкой над картой.

## Готовые экраны

- **Рабочий день:** показатели, список маршрутов, интерактивная карта, расписание, проблемные заявки.
- **Заявки:** поиск, фильтры, требования, статусы и карточка с объяснением.
- **Инженеры:** навыки, транспорт, смена, количество заявок и пробег.
- **Эффективность:** сравнение обязательных метрик с базовым алгоритмом, изменения после события.
- Модальные окна загрузки данных и срочного события; состояния без плана, расчёта, ошибки импорта, пустого поиска и отсутствия картографической подложки.

## Подключение бэкенда

Компоненты обращаются к объекту `api` в `frontend/src/api.ts`. Замените реализацию двух методов `plan` и `replan` HTTP-запросами, сохранив интерфейс `DispatchApi` из `frontend/src/types.ts`.

`frontend/src/demo.ts` → `api.plan()` → `PlanPair` → React-экраны.

`событие` + `текущий Plan` → `api.replan()` → `ReplanResult` → обновлённые экраны.

Типы, семантика времени и предлагаемый HTTP-контракт описаны в [docs/API_CONTRACT.md](docs/API_CONTRACT.md). План работы команды и связь с требованиями кейса — в [docs/ACTION_PLAN.md](docs/ACTION_PLAN.md). Пользовательский путь и состав экранов — в [docs/UX_FLOW.md](docs/UX_FLOW.md).

## Данные и допущения

- Демонабор создан для интерфейса. Имена, навыки, транспорт, координаты, длительности и окна синтетические; он не является результатом анализа исходных CSV.
- Пример импорта: [data/examples/demo-dataset.json](data/examples/demo-dataset.json). Импортируется единый JSON с заявками и инженерами, до 100 заявок и 30 инженеров. CSV пока не импортируется.
- Все времена относятся к одному дню, локальное время Москвы; ночные смены не поддерживаются.
- Окно ограничивает **начало работы**. Завершение работы может быть позже конца окна, но должно быть не позже конца смены. Возвращение на базу не требуется.
- Расстояния — геодезические по прямой. Скорости для демонстрации: автомобиль 28, пешеход 5, велосипед 15, общественный транспорт 18 км/ч. Пробки, дорожная сеть, пересадки, оборудование и перерывы не моделируются.
- Карта использует Leaflet и тайлы OpenStreetMap; линии соединяют точки по прямой. При отсутствии сети точки остаются на координатной подложке. Google Fonts необязателен: есть системный шрифт. Для офлайн-защиты можно записать видео или заранее подготовить локальную картографическую подложку с подходящими условиями использования.
- Локальная эвристика перебирает несколько порядков заявок. Сравнивает: больше назначенных заявок → меньше исполнителей → меньше пробег. Наличие неназначенной заявки при подходящих ресурсах не доказывает невозможность решения; объяснение в интерфейсе это учитывает.
- Базовый алгоритм идёт по исходному порядку заявок и инженеров, добавляет работу в конец маршрута первого подходящего свободного исполнителя.
- В событии срочная заявка рассматривается первой среди оставшихся. Работы с `start < event.at` сохраняются. Уже начатая работа завершается, затем инженер продолжает с её адреса. Положение инженера в пути не моделируется: это ограничение прототипа, которое нужно решить на сервере.
- Поддерживается один сценарий события: срочная заявка. Это соответствует обязательному MVP кейса. Повторный запуск сценария — через сброс демонабора.
- Состояние хранится в памяти вкладки. Обновление страницы сбрасывает его; экспорт JSON позволяет сохранить результат для обсуждения. Импорт экспортированного плана отдельно не реализован.
- Бренд «Контур» — рабочее название прототипа, не официальный продукт «Билайн».

## Проверки

```bash
# Из папки frontend/
npx playwright install chromium
npm test
```

Перед первым запуском тестов установите браузер: `npx playwright install chromium` (из `frontend/`). `npm test` автоматически собирает приложение и запускает preview-сервер. В GitHub Actions выполняются те же проверки.

Тесты проверяют ограничения и пересчёт метрик, сохранение начатых работ, проверку JSON, основной пользовательский путь, экспорт, мобильную навигацию и отсутствие горизонтального переполнения на ширине 390 px. Скриншоты и трассировки сохраняются в `frontend/test-results/`, не изменяя файлы документации.

## Структура

```text
frontend/          React + TypeScript, конфигурация, зависимости и тесты
backend/           зона серверного API и алгоритма; реализация ещё не добавлена
data/examples/     синтетический JSON для импорта и скачивания из интерфейса
scripts/           зона скриптов подготовки данных и обслуживания проекта
docs/              контракт API, UX, план команды и готовые скриншоты
.github/           CI и шаблон Pull Request
netlify.toml       сборка frontend/ и публикация frontend/dist/
CONTRIBUTING.md    правила совместной разработки
```

Сейчас запускается только фронтенд, включая демонстрационный расчёт в браузере. Сервер и обработка исходных CSV ещё не реализованы. Каждый компонент хранит зависимости и тесты в своей папке; npm-команды выполняются из `frontend/`.

Для участия в разработке см. [CONTRIBUTING.md](CONTRIBUTING.md). Контракт API изменяем согласованно между фронтендом и бэкендом. Примеры в `data/examples/` Vite публикует как статические файлы; исходные данные хакатона туда не помещаем.
