# Контур — рабочее место выездного сервиса

Прототип для кейса «Билайн Бизнес»: поддержка принимает заявки и выполняет назначенные выездные работы, диспетчер планирует маршруты, корректирует расписание и сравнивает эффективность. Визуальная система адаптирована по Polaris.

## Запуск

Node.js 24 и npm (версия в `.nvmrc`).

```bash
git clone https://github.com/enkayzz/beeline-dispatcher.git
cd beeline-dispatcher/frontend
npm ci
npm run dev
```

Откройте адрес Vite, обычно http://127.0.0.1:5173. Для существующей локальной копии npm-команды выполняются из `frontend/`.

```bash
npm run build
npm run preview -- --port 4173
npx playwright install chromium
npm test
```

Тесты сами собирают приложение и запускают preview. Скриншоты и трассировки — в `frontend/test-results/`; CI проверяет ограничения и браузерные сценарии.

## Что попробовать

1. В рабочем месте поддержки нажать **«Создать заявку»**. Заполнить адрес, координаты, окно и тип работ.
2. Переключиться в шапке на **«Дмитрий · Диспетчер»**, открыть **«Маршруты и расписание»**, построить план.
3. Открыть **«График поддержки»**: настроить постоянные часы, транспорт, запас оборудования и право сотрудника редактировать свои данные.
4. В рабочем месте поддержки открыть **«Моё расписание»**: посмотреть дневную шкалу, задания и добавить период недоступности.
5. Вернуться к диспетчеру, открыть работу, изменить исполнителя/начало и нажать **«Назначить и пересчитать»**. Недопустимое назначение покажет причину и не изменит план.
6. На **«Эффективности»** посмотреть отклонения рабочего плана от предложения системы и изменения отдельных заявок.
7. Исправить причину неназначения: условия заявки или допуски/запас специалиста поддержки, затем назначить работу.
8. В поддержке обновить выполнение своей заявки до 50%, затем 100%. В диспетчерском рабочем месте подтвердить завершение.
9. Проверить фильтры, историю заявки, отмену с причиной, сохранение после обновления страницы и экспорт плана.
10. Перейти к предыдущей/следующей неделе в личном расписании или выбрать «Рабочую дату». Для будущего дня создать либо импортировать заявки и построить план. Вернуться к сохранённому дню: его назначения и статусы остаются на месте.

В поддержке счётчик меню, фильтр «Назначенные мне» и «Моё расписание» показывают один набор работ текущего сотрудника за выбранную дату, включая закрытые и отменённые после назначения. «Созданные мной обращения» — отдельный фильтр: автор заявки и её исполнитель могут различаться. В диспетчерском меню считается весь участок, а показатель «Назначено» в планировании считает только работы в маршрутах. Поиск и фильтры пересчитывают сводку над доской; счётчик меню остаётся общим за день.

## Ограничения прототипа

- Это два переключаемых рабочих места в одном браузере, **без серверной авторизации и синхронизации между устройствами**. Поддержка принимает обращения и выполняет назначенные выездные работы.
- Состояние и сохранённые дни хранятся в localStorage. Импорт заменяет только указанную дату после подтверждения, остальные дни сохраняются. Полный сброс удаляет все сохранённые дни. Экспорт включает архив дней; его обратный импорт пока не реализован.
- История до внедрения календаря отсутствует, если её не загружали или не сохраняли. Навигация не создаёт вымышленные заявки: новый день пустой, пока заявки не созданы или не импортированы. Постоянный график наследуется от ближайшего более раннего сохранённого дня (либо первого доступного).
- Стартовый набор синтетический для UI; это ещё не расчёт на CSV постановщика. Поддерживается до 100 заявок и 30 специалистов поддержки на один день/участок.
- Время Москвы. Окно ограничивает начало, завершение должно укладываться в смену. Возврат на базу не моделируется.
- Приоритет: авария → подключение → ремонт/дозаказ. Модель расходуемого оборудования — роутеры.
- Длительности работы и документов: подключение 70, авария 80, ремонт 30, дозаказ 20 минут. Нормативные 20 минут дороги заменяются рассчитанным временем. Это явно принятое допущение, требующее подтверждения.
- Расстояния по прямой; средние скорости: автомобиль 28, пешком 5, велосипед 15, общественный транспорт 18 км/ч. Геокодирование, дорожная сеть, пробки и фактическая позиция пока не подключены.
- Завершённые работы сохраняются как история маршрута и не назначаются заново. Начатые работы фиксируют префикс маршрута. Эвристика не доказывает оптимальность или невозможность назначения.
- Карта требует сеть для тайлов OpenStreetMap; без неё точки и линии остаются доступны.

## Структура

```text
frontend/src/pages/        заявки, расписание, эффективность
frontend/src/components/  формы, карточка заявки, общие элементы
frontend/src/domain/      состояние рабочего дня и планировщик
frontend/src/MapView.tsx  карта Leaflet
frontend/tests/           проверки ограничений и пользовательских сценариев
backend/                  место для будущего серверного API
data/examples/            пример импорта (публикуется вместе с фронтендом)
scripts/                  место для подготовки исходных данных
docs/                     контракт, решения и план развития
.github/                  CI и шаблон PR
```
